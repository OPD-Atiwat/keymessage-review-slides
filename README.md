# วงคุย Key Message

เว็บสาธารณะของโปรเจกต์ `creator-review-slides` อยู่ที่ `https://creator-review-slides.opendurian.dev` ต้องเข้าสู่ระบบก่อนเห็นตาราง ภาพ และบันทึก การจำกัดด้วยไอพีหรือพร็อกซีไม่ใช่การล็อกอิน

ตัวเลขผลลัพธ์ชุดนี้ถึง 8 พ.ย. 2569 ตามเวลาไทย พฤศจิกายนคือ 1–8 พ.ย. ไม่ใช่เดือนเต็ม การตรวจสถานะ 8 พ.ย. 11:39 น. เป็นคนละเรื่อง

สำรับ 12 หน้าสำหรับคุยข้อความแอดของสี่เล่ม (Mind, ออฟฟิศ, Survival Guide, กับดัก) จากสแนปชอต 8 พ.ย. 2569 แคมเปญแชทเท่านั้น ไม่รวมยอดวันที่ 8 ที่ยังไม่จบวัน

ป้ายครีเอเตอร์เป็นตัวกรองในรายการแอด ไม่ใช่แกนของเรื่อง

## สิ่งที่เจ้าของตั้งบนแดชบอร์ดครั้งเดียว

โปรเจกต์นี้เท่านั้น ไม่ใช่ฐาน KPI

เปิด [ฐานข้อมูล](https://mcp.opendurian.dev/dashboard?project=creator-review-slides&section=database) แล้วคัดลอกสายเชื่อมฐาน **prod** ไปวางเป็น `DATABASE_URL` ใน [Secrets](https://mcp.opendurian.dev/dashboard?project=creator-review-slides&section=secrets)

เหลืออีกคีย์เดียวที่ต้องตั้ง:

- `BOOTSTRAP_PASSWORD` — รหัสที่เจ้าของเลือกเอง ยาวอย่างน้อย 10 ตัว

ไม่ต้องตั้ง `SESSION_SECRET`, `EDITOR_PASSWORD_HASH`, หรือ `TRUST_PROXY` เซิร์ฟเวอร์สร้างรหัสแฮชแบบ scrypt และกุญแจเซสชันเอง แล้วเก็บในฐานของโปรเจกต์นี้ คุกกี้เป็น HttpOnly, Secure, SameSite=Lax เพราะเบราว์เซอร์เปิด `https://creator-review-slides.opendurian.dev` เสมอ

หลังเข้าเว็บได้แล้ว ลบ `BOOTSTRAP_PASSWORD` ออกจาก Secrets ได้ ถ้ายังทิ้งไว้ ระบบไม่เปลี่ยนรหัสที่มีอยู่แล้ว รหัสเข้าเว็บคือรหัสที่ตั้งในคีย์นั้น

การ push ไป `main` บน GitLab ของบริษัทเป็นตัวสั่งดีพลอย GitHub pull request ไม่ดีพลอย

## ก่อนดีพลอยต้องตรง Ads Manager

ทุกช่วงที่เว็บแสดงต้องมีไฟล์ `data/meta_reference_<period>.json` จาก Meta insights ของช่วงนั้น ทั้งระดับแอดและระดับแคมเปญ ตัวเลขที่ใช้คือ spend, purchases = `omni_purchase`, revenue = `action_values` ของ `omni_purchase`, messages = `onsite_conversion.messaging_conversation_started_7d`

ยอดเล่มต้องเท่ากับผลรวมระดับแคมเปญของแท็ก `[Mind]` `[Coworkers]` `[SurvivalGuide]` `[Trap]` ทุกวัตถุประสงค์ คลาดเคลื่อนได้ไม่เกิน 1 บาท และจำนวน purchases กับ messages ต้องตรง แถวแอดต้องตรงกับระดับแอดทีละแอด ถ้าผลรวมระดับแอดต่ำกว่าระดับแคมเปญ เว็บต้องมีแถวเดียวชื่อ `แอดที่ Meta ไม่ส่งรายแอด (ลบแล้ว)` ในตารางเล่มนั้น และยอดนั้นอยู่ในกลุ่มไม่ทราบ Creator ผลรวมแถวบวกแถวนี้ต้องเท่ากับยอดเล่ม ห้ามให้ยอดแอดกับยอดเล่มคลาดกันโดยไม่แสดงแถว

แคมเปญที่ไม่มีแท็กเล่มต้องอยู่ใน `otherProductCampaigns` ของไฟล์ช่วงนั้นแบบระบุชื่อตรงตัว แอดของแคมเปญนั้นไม่ต้องอยู่บนเว็บ แคมเปญที่ไม่ได้ระบุและไม่มีแท็กเล่มทำให้การตรวจไม่ผ่าน

รัน `npm run reconcile` ก่อนดีพลอย คำสั่งนี้เขียนบรรทัดใน «วิธีนับ» เมื่อทุกช่วงผ่าน และจบด้วยรหัสไม่ใช่ 0 เมื่อไม่ผ่าน การ build image รันคำสั่งเดียวกัน ถ้าไม่ผ่าน image ไม่ถูกสร้าง แพลตฟอร์มนี้สั่งดีพลอยจากการ build Dockerfile ตอน push `main` ไม่ได้ใช้ GitLab CI ไฟล์ pipeline จึงกันดีพลอยไม่ได้

การอัปเดตตัวเลขต้องนำไฟล์ Meta รอบใหม่มาใส่ `data/` ทุกช่วงที่เว็บแสดง แล้วให้คำสั่งนี้ผ่านก่อน push `main`

## บันทึก

หน้าตารางและสไลด์ไม่มีช่องบันทึกท้ายหน้า แท็บ **วิเคราะห์ต่อยอด** เป็นหน้าที่เดียวสำหรับรายการข้อความที่เลือกเองจากแถวในตาราง แล้วเขียนบันทึกวิเคราะห์ ระบบไม่จัดอันดับให้และไม่แนะนำให้เลือก ช่วงผลลัพธ์และเล่มที่กำลังดูไม่เปลี่ยนตอนกดเลือก รายการที่เลือกจำเล่ม เดือน Content ช่วงผลลัพธ์ และตัวเลขของแอดนั้น เก็บใน PostgreSQL ของโปรเจกต์นี้ เอาออกจากรายการต้องยืนยันถ้ามีบันทึกแล้ว บันทึกเก่าที่เคยอยู่บนสไลด์ไม่ถูกลบ
